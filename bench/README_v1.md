# 对照测试第一版：降噪耳机（已被第二版"八颗行星"取代，见 README.md）

同一段旁白，交给 AI 做讲解动画，一遍不装卡字，一遍装上，看画面有没有落在关键词上。

## 怎么测的

- **素材**：一段 18.75 秒的旁白，讲"降噪耳机为什么能降噪"，五句话，每句一个关键词（`anc/script.txt`）。旁白是 AI 克隆声音配的（`anc/narration.wav`）。
- **谁来做**：Claude Code，两个模型（Opus、Sonnet），每个模型做两遍：一遍不装卡字，一遍装上。一共四遍。
- **怎么隔离**：四遍各在一个独立的空目录里，以子任务（subagent）的方式运行，只允许读写自己的目录。不装卡字的那两遍，目录里没有卡字的任何文件。
- **提示词**：四遍完全一样（`prompt.txt`），装卡字的两遍多两行，告诉它 skill 装在哪（`prompt_kazi_extra.txt`）。提示词里没有提"卡字""关键词要卡上"之类的要求，只说"关键词用星号标出来了"。
- **中途不干预**：做的过程中没有人回复它；做出来的片子一帧没改。
- **怎么量**：`tools/kazi_check.py`，关键词时刻用同一张逐字对齐表（`anc/timeline.json`）。判断规则：关键词念出前 0.35 秒到后 0.15 秒里画面的变化量，至少是再往前那一秒的 1.5 倍。随机基线：把同样的判断放到旁白里的每一个时刻上，看有多大比例也会被判"卡上"；基线高说明画面一直在乱动。

## 结果

| 这一遍 | 卡上的关键词 | 随机基线 | 
|---|---|---|
| Opus，不装 | 1 / 5 | 22% |
| Opus，装上卡字 | 5 / 5 | 37% |
| Sonnet，不装 | 0 / 5 | 2% |
| Sonnet，装上卡字 | 5 / 5 | 30% |

合起来：不装的两遍，十个关键词卡上一个；装上的两遍，十个全卡上。每个关键词的明细在 `results_anc.json`，四段成片在 `videos_v1/`。

我们看了四遍的做法，几个观察：
- 装上卡字的两遍，都先用对齐模型给每个字标了时间，再按时间表落动作。它们的第一版也没有全部卡上，是自己跑完检查工具、看到哪个词没卡上，改到全过的。
- Opus 不装的那遍，自己想到了用语音识别对时间，方向是对的；但背景一直在匀速动，关键词那一下不够显眼，量下来只卡上一个。
- Sonnet 不装的那遍，关键词的时刻是估出来的，写死在代码里；画面又一直匀速在动，五个都没卡上。

## 局限，先说清楚

- **样本很小**：每组只跑了一遍，一段旁白，五个关键词。这是一个演示，不是严谨的评测。结果会随模型版本变化。
- **卡字率只量"落没落在关键词上"**，不量好不好看。四段片子的观感，建议你自己看一遍 `videos_v1/`。
- 装卡字的那两遍多知道了一条信息（"有个 skill 在这里"），这本身就是被测的东西。
- 判断规则是我们自己定的（理由见 `docs/06_检查和发布.md`），你可以改阈值重新量。

## 自己跑一遍

```bash
python bench/run.py ~/kazi-bench --topic anc --python $(which python)   # 建四个目录，每个里面一份 PROMPT.txt

```
