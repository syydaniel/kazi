# 对照测试：装和不装卡字

> **英文版重测（2026-11-07）**：同一个题目，英文旁白，四遍用同一套美术和版式，只比动的时机。结果 Opus 不装 5/9、装上 9/9；Sonnet 不装 2/9、装上 1/9（读了 SKILL.md，但跳过了对齐和逐帧检查）。方法、原始文件和四段成片见 `planets_en/`（英文说明）。

同一段旁白，交给 AI 做讲解动画，一遍不装卡字，一遍装上，看画面有没有落在关键词上。

现在用的是第二版题目"太阳系的八颗行星"：旁白念到哪颗星，哪颗星就该在这一下亮起来，对没对上一眼就能看出来。第一版用的是"降噪耳机为什么能降噪"，四段片子看着差不多，差别不明显，记录留在 `README_v1.md`。

## 怎么测的

- **素材**：一段 39.3 秒的旁白，九句话，九个关键词（八颗行星这个总称，加上八颗行星的名字），见 `planets/script.txt`。旁白是 AI 克隆声音配的（`planets/narration.wav`）。
- **谁来做**：Claude Code，两个模型（Opus、Sonnet），每个模型做两遍：一遍不装卡字，一遍装上。一共四遍。
- **怎么隔离**：四遍各在一个独立的空目录里，以子任务（subagent）的方式运行，只允许读写自己的目录。不装卡字的那两遍，目录里没有卡字的任何文件。
- **提示词**：四遍完全一样（`prompt.txt`，题目由 `run.py --topic` 填进去），装卡字的两遍多两行，告诉它 skill 装在哪（`prompt_kazi_extra.txt`）。提示词里没有提"卡字""关键词要卡上"之类的要求，只说"关键词用星号标出来了"。
- **中途不干预**：做的过程中没有人回复它；做出来的片子一帧没改。
- **怎么量**：`tools/kazi_check.py`，关键词时刻用同一张逐字对齐表（`planets/timeline.json`）。判断规则：关键词念出前 0.35 秒到后 0.15 秒里画面的变化量，至少是再往前那一秒的 1.5 倍。随机基线：把同样的判断放到旁白里的每一个时刻上，看有多大比例也会被判"卡上"；基线高说明画面一直在乱动。
- **差了多少**：`offsets.py` 在每个关键词前 3 秒到后 2 秒里，找画面变化最大的那一刻，算它离关键词多远；`--json` 还会存下每 0.05 秒的画面变化曲线，可以拿来画图。

## 结果

| 这一遍 | 卡上的关键词 | 随机基线 |
|---|---|---|
| Opus，不装 | 1 / 9 | 36% |
| Opus，装上卡字 | 9 / 9 | 33% |
| Sonnet，不装 | 0 / 9 | 26% |
| Sonnet，装上卡字 | 9 / 9 | 31% |

合起来：不装的两遍，十八个关键词卡上一个；装上的两遍，十八个全卡上。每个关键词的明细在 `results_planets.json`，离关键词多远和画面变化曲线在 `offsets_planets.json`，四段成片在 `videos/`。

几个观察（逐帧核对过）：
- **不装的两遍，行星一颗都没放错。** 它们都想到了用语音识别找每句话的起点，念到哪颗，画面上就是哪颗。
- **差在动的时机。** 不装的两遍，画面最大的那一下动作，十八处里有十二处比名字早，早的那些中间值是 1.4 秒左右；另外六处晚了半秒到一秒半。名字念出来时，画面往往已经停了，那一下反而不显眼。
- 举两个例子：念到"土星"的那句，Sonnet 不装的那遍，"土星"两个大字比声音早一秒就摆好了；装上的那遍，念到"土星"那一下，整个画面一闪，名字亮起来。念到"木星"的那句，Opus 不装的那遍，名字还没念出来，木星已经推到画面中间；装上的那遍，念到"木星"，名字正好亮起来。
- **装上卡字的，第一版也不一定全对。** Opus 装上的那遍，第一版卡上 8 个，水星没卡上：它从全景一口气推到水星，放大 14 倍，关键词前一秒画面就已经在动了。跑完检查工具以后，它自己把这一下拆成两段（先在句间停顿里推到太阳附近停稳，再在"水星"上推到特写），改到 9 个全过。
- 装上的两遍落点方式不一样：Sonnet 那遍的动作从关键词开始，曲线上的尖峰正好压在关键词上；Opus 那遍的动作在关键词那一刻到位，尖峰紧挨在关键词前面一点。两种都算卡上。

## 局限，先说清楚

- **样本很小**：每组只跑了一遍，一段旁白，九个关键词。这是一个演示，不是严谨的评测。结果会随模型版本变化。
- **卡字率只量"落没落在关键词上"**，不量好不好看。四段片子的观感，建议你自己看一遍 `videos/`。
- 装卡字的那两遍多知道了一条信息（"有个 skill 在这里"），这本身就是被测的东西。
- 判断规则是我们自己定的（理由见 `docs/06_检查和发布.md`），你可以改阈值重新量。

## 自己跑一遍

```bash
python bench/run.py ~/kazi-bench --python $(which python)   # 建四个目录，每个里面一份 PROMPT.txt（默认题目是八颗行星，--topic anc 换回第一版）
# 在 Claude Code 里，按目录名选模型（opus / sonnet），把对应目录里 PROMPT.txt 的全文发给它，等它做出 out/final.mp4
python bench/score.py ~/kazi-bench --json bench/results_mine.json
python bench/offsets.py ~/kazi-bench --json bench/offsets_mine.json
```

想测别的 AI 助手也可以：把 `.claude/skills/kazi/` 换成它约定的 skill 目录，提示词照用。
