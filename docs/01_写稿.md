# 第一步：写稿

稿子是给耳朵听的。眼睛可以往回扫，耳朵只能听一遍，很多句子看着通顺，一念就拗口。

## 稿子格式（script.txt）

```
# 井号开头是注释
[段落名]
一句话一行，*关键词* 用星号包起来。 | 0.4
念法和字幕不一样时写 {F F M peg=>FFmpeg}，左边给配音念，右边给字幕看。 | 0.3
@gap 5 demo
```

- `| 0.4`：这句收声到下一句开口，听到的空白有多长（秒）。不写默认 0.4。配音之后用 pace.py 和 `timeline.py --speech-gap`，听到的就是写的这个数（见第二步）。怎么定见下面的停顿表。
- `@gap 秒数 名字`：没有旁白的空当，比如放一段演示、一段试听。名字会写进 timeline.json 的 gaps，画面用它找位置。
- `[段落名]`：章节。timeline.json 里每段有起止时间，章节卡、进度条都用它。
- 带 `【】` 的句子是占位（等数据），不配音，时长按字数估。

## 规矩和原因

| 规矩 | 原因 |
|---|---|
| 两个标点之间不超过 22 个字，长短句穿插 | 一口气念不完会抢气、变调；全是短句又像念口号 |
| 每句只标一个关键词 | 画面要落在这个词上；一句两个落点，观众不知道看哪 |
| 关键词尽量是动词或者变化 | 下一步要"画动词"，名词只能画成插图 |
| 一条字幕最多一个关键词 | 字幕里变色的词就是重音，多了就不是重音了 |
| 旁白说过的整句不要再上屏 | 冗余原则：同一句话又听又读，理解反而变差（Mayer 2017，效应量 d=0.87） |
| 开头 30 秒内交代：观众可能有的误解、一个具体数字、这条片子讲的是哪个工具或方法 | 留存最容易掉在开头；观众要先知道"看完能得到什么" |
| 用了 AI 配音，在平台的 AI 生成内容声明和简介里写明，旁白里不反复强调 | 该说明的要说明；可观众是来看内容的，一遍遍提醒"这是 AI 声音"会把注意力从内容上拉走 |
| 专有名词、英文、数字写念法 | 配音模型会把 FFmpeg 念成一个怪词；把 443 念成"四四三" |
| 少用"最后""总之" | 观众听到会以为要结束了，开始划走 |

## 写完以后

```bash
python tools/lint_script.py script.txt
```

它会查：一口气太长、字幕一行超过 16 个字、一条字幕里多个关键词、破折号、占位句，并按每秒 5 个字估算每段和全片的时长。
有问题就改，没问题把稿子给用户看（停一）。

## 用词：完整的词、成语、典故

| 规矩 | 原因 |
|---|---|
| 不拿单字当词用，"估"写成"估算""估计"，"测"写成"测量" | 单字念出来很突兀，耳朵还容易听成别的字；屏幕上单独一个大字也看不出意思 |
| 一节的结论处，可以放一个成语、俗语或歇后语点题 | 一句熟语比一长串解释好记，观众会拿它去复述；例：差之毫厘，谬以千里（误差累积）；工欲善其事，必先利其器（工具）；画龙点睛（画动词）；喧宾夺主（配乐让位）；胸有成竹（先想清楚）；授人以鱼，不如授人以渔（分享方法）；是骡子是马，拉出来遛遛（实测）；金无足赤（讲不足） |
| 一节最多一处，全片八到十处 | 用多了像在背成语词典，反而显得刻意 |
| 引用古人的话要核对出处，拿不准就只说"古人说" | 出处说错，评论区一定有人指出来，整条片子的可信度跟着掉 |
| 熟语要贴着这一节的意思用，别为了用而用 | 观众听到熟语会停下来想"这跟刚才说的有什么关系"，贴切才有回报 |

屏幕上的背景大字也一样：用完整的词或者四字成语，不用单字。比如讲误差累积，背景放"差之毫厘"，不放一个"估"字。

## 说完整，说成人话

AI 写口播稿最常见的毛病，是为了紧凑把句子成分省掉，再用单个字当动词。看着简洁，念出来像电报，一听就是机器写的。

| 规矩 | 例子 |
|---|---|
| 主语、宾语、量词、连接词补完整 | "每句配四遍再挑" → "每句话配了四遍以后，再进行挑选"；"模型换了，为什么还在，这套东西就还能接着用" → "就算模型都换掉了，这些为什么还在，所以这套方案依然能够接着使用" |
| 动词以两个字以上为主，单字和多字交替着用 | "跟着画面走" → "跟随画面一起变化"；"你信吗" → "你相信吗"；"测过" → "测试过"。全部换成双字又会显得书面，口语里本来就是长短混着说 |
| 关键词不用单字 | "*测*" → "*测量*"，"*落*" → "*落脚*"。单字关键词在屏幕上看不出意思，念出来也容易被听成别的字 |
| 多用说话时的衔接 | "我们先来看看""那具体怎么使用呢""说白了""接下来"。讲解视频是在跟人说话，不是在念说明书 |
| 句子长短交替 | 连着三句一样长，节奏就平了；一句长的解释后面，跟一句短的结论 |

写完念一遍：哪里要换气、哪里念着别扭，就在哪里改。

## 停顿怎么定

停顿按意思定，不按标点定。下面是这条片子实际用的几档（听到的空白，秒）：

| 停顿 | 用在哪里 |
|---|---|
| 0.34 到 0.40 | 同一个意思往下接；问句后面马上回答；后面紧跟一段演示或试听 |
| 0.43 | 普通的句与句之间 |
| 0.47 到 0.52 | 换了一层意思，但还在同一段里 |
| 0.56 到 0.64 | 一段讲完；一个结论说完 |
| 0.7 | 金句、成语点题之后，留一点时间让观众消化 |
| 0.95 | 大的转折，比如开头讲完问题、亮出方法名字之后 |
| 1.2 | 全片最后一句 |

章节之间用 `@gap 1.1 名字` 留出章节卡的时间。同一档用久了也会显得机械，相邻几句之间可以错开一点（0.43、0.47、0.43）。

## 互动提示放在哪里

参考做法：每一种只说一次，放在它最自然的位置，三连放在全片最后一句。

| 提示 | 放在哪里 | 怎么说 |
|---|---|---|
| 收藏 | 讲完"后面有几个步骤"之后 | "后面的六个步骤都分好了章节，你可以先收藏起来，等真正动手的时候，再回来翻看" |
| 点赞 | 一大块干货讲完的时候 | "如果你觉得有用的话，可以点个赞，让我知道这样讲解你能听得进去" |
| 评论 | 有一个观众能回答的问题时 | "你觉得四段里哪一段最好？可以在评论区打个数字" |
| 关注 | 说完"之后还会更新什么"之后 | "有了新版本，我会第一时间更新……想第一时间看到的话，记得点个关注" |
| 三连 | 最后一句 | "如果这期视频对你有帮助，请帮我点个赞，投个币，收藏一下，我们下期再见" |

写稿时也要避开容易读错的多音字，替代表见 [第二步](02_配音.md#多音字)。
