# 第二步：配音

## 用克隆声音配

```bash
python tools/voice.py script.txt vo --ref 声音样本.wav --takes 4
```

- 声音样本：10 秒左右、安静环境、正常语速的一段录音，旁边放同名的 `.txt` 写逐字稿（`声音样本.txt`）。
- 模型：阿里开源的千问 Qwen3-TTS（`mlx-community/Qwen3-TTS-12Hz-1.7B-Base-bf16`，通过 mlx-audio 在本机跑）。第一次运行会下载模型。
- 每句生成 4 遍，每一遍都用 Whisper（large-v3-turbo）转回文字，和原稿比对：
  - 吻合度低于 0.9 的直接扣分；语速明显异常的扣分；吻合度差不多时再看音高起伏，太平的像念经。
  - 吻合度排在起伏前面：做这条片子时，有一遍吻合度 0.94、起伏最大，被挑中了，听回来"不装"像"不中"，同一句另外两遍都是 1.0。现在吻合度差 0.05，就足够压过起伏的差别。
  - 留分最高的一遍到 `vo/lines/L001.wav`，所有遍都留在 `vo/takes/`。
- 按念法内容缓存：改了哪句只重配哪句，插句删句不影响别的句子。换了参考段或声纹的句子会重配。
- 做英文片，参考录音换成你自己说的英文，见下面的「英文片」。

## 为什么要另一个 AI 来听

配音模型念错字的时候，自己是不知道的。转回文字一比，问题就露出来了：
- **念错字**：多音字读错、英文缩写念成一个词。改念法 `{念法=>字幕}`。
- **字没错，听起来像别的意思**：同音词撞车。识别结果和原稿不一样，但每个字的读音都对。这种要改写句子，换个说法。
- 识别出来的同音字（"轻"和"清"、"托"和"拖"）不算错，看一眼就行。

人只要整体试听一遍（停二），不用一句一句核对。

## 想整体快一点

```bash
python tools/tempo.py vo vo_fast --tempo 1.07
```

变速不变调（ffmpeg atempo，专门给语音用的 WSOLA 算法）。实测 12 句加快 7%，语音识别吻合度和原声一样。不要为了快重新生成：重新生成要重新挑遍数，念对的那一遍可能就没了。

## 停顿规整

配音模型每句开头结尾自带的静音长短不一（0 到 0.5 秒），句子里的逗号有时一口气念过去，有时又拖很久。
稿子里写"这句后面停 0.4 秒"，实际听到的空白可能是 0.2 秒，也可能是 1 秒：有的段落连得太紧，有的又太松。

```bash
python tools/pace.py vo_fast vo_paced --report vo_paced/report.tsv
python tools/timeline.py script.txt vo_paced timeline.json --wav vo_paced/narration.wav --speech-gap
```

pace.py 只动静音，不动念出来的声音：
1. 句首句尾：按音量找出真正开口和收声的位置，前面只留 0.04 秒、后面只留 0.08 秒，记进每句的 json。
2. 句内标点：量出每个标点处实际的静音，短了就在静音最深处补一段，长了就从中间剪掉一段，剪和补都落在最安静的那一帧，换气声尽量不切开。
3. 补了多少、剪了多少，后面每个字的对齐时间跟着加减，不用重新对齐；对齐器把标点处的静音算进下一个字的，也按实际静音修正（不然字幕会比声音先亮）。

句内标点的静音范围（秒，按最终语速）：

| 标点 | 最短 | 最长 |
|---|---|---|
| 顿号 | 0.06 | 0.18 |
| 逗号 | 0.14 | 0.32 |
| 冒号 | 0.16 | 0.36 |
| 分号 | 0.24 | 0.42 |
| 句号、问号、叹号（句中） | 0.30 | 0.48 |

加了 `--speech-gap` 以后，稿子里的 `| 0.4` 就是"这句收声到下一句开口，听到的空白是 0.4 秒"。句与句之间按意思定停顿，见 [第一步的停顿表](01_写稿.md#停顿怎么定)。

## 多音字

回听查的是"转回文字对不对得上"，可是识别模型会按上下文猜字："往后数（shǔ）十句"念成了"数（shù）十句"，识别出来照样是"数十句"，比对发现不了。

```bash
python tools/polyphone.py timeline.json vo_paced/narration.wav --out vo/polyphone
```

它会挑出可能读错的多音字，拼成一条试听音频 `flagged.wav`。要知道它的局限：识别模型的语言习惯会盖过读音差别，列出来的大多是误报；拿读错的录音做对照时，它也可能漏掉。所以它只负责缩小范围，听还得靠人，"没报出来"不等于"没读错"。

更稳的办法是写稿时就避开。下面是做这条片子时换掉的写法（预防为主，括号里是容易混的读音）：

| 容易读错 | 换成 |
|---|---|
| 拗口（ào / niù） | 磕磕绊绊、不顺口 |
| 长高（zhǎng / cháng） | 拔高 |
| 数十句（shù / shǔ） | 几十句 |
| 一目了然（liǎo / le） | 一眼就能看懂 |
| 它就还你（huán / hái） | 它也只能做出 |
| 就得写成、还得靠（děi / de） | 就要写成、还要靠 |
| 当例子（dàng / dāng） | 作为例子 |
| 用不着（zháo / zhe） | 不需要 |
| 空当（kòng / kōng，dàng / dāng） | 停顿的地方 |
| 不断去试 | 反复尝试（四遍都被听成"不断去世"，读音没错，是同音撞车） |

成语和术语里的多音字（差之毫厘的"差"、重叠动作的"重"），模型通常念得对，换掉又会损失意思，可以保留，但要列进人工试听的清单。

**声母不同的多音字，可以用声学比对来查。** 比如"卡"有 kǎ（卡字）和 qiǎ（卡住）两个读音，声母一个是 k、一个是 q，开头那几十毫秒的频谱差得很远。做法：把全片每个"卡"字开头那一小段的频谱特征算出来，再拿一批读音确定是 k 声母的字、一批确定是 q 声母的字各算一份当参照，看每个"卡"离哪一组近。做这条片子时 39 个"卡"全部落在 k 那一组。声调不同、声母相同的（"数"shǔ 和 shù）这样分不出来，还得靠耳朵。

**识别结果里的同音字不算念错。** 回听比对时，"锈红色"被识别成"绣红色"、"刮得最猛"被识别成"瓜的最猛"、"图鉴"被识别成"图件"，读音其实都对，只是识别模型选了另一个同音字，吻合度会掉到 0.85 到 0.95。看到吻合度不是 1，先看是不是同音字，再决定要不要重配。

## 英文片：用你自己说的英文当参考

拿中文录音去克隆英文旁白，声音能用，可是像你的程度低一截。做《卡字》英文版时实测：10 句英文，每种参考每句生成 5 遍，用千问自己的声纹编码器，拿你另外录的英文（不进参考段）来量像不像。

| 克隆用的参考 | 千问声纹相似度（所有遍平均） | 最差的一遍 |
|---|---|---|
| 中文录音 `ref.wav` | 0.973 | 0.936（字都念对了，整句声音变了样） |
| 中文克隆出来的一段英文 | 0.974 | 0.966 |
| 你自己念的英文，10 秒两句 | 0.986 | 0.978 |
| 同上，声纹换成所有英文录音的平均 | 0.988 | 0.980 |

上限是你本人两段真录音互相比：0.992。换成英文参考以后，10 句里 10 句都更像你。

### 录什么

1. 朗读稿用 `tools/ref_read_en.txt`：4 段 17 句，225 个词，约 80 秒，覆盖了 th、v 和 w、r 和 l、词尾辅音、连读弱读、升调降调这些中文母语者和英文母语者差得最多的地方，用词和讲解视频一类。
2. 和中文参考用同一支麦、同样的距离和增益。关掉降噪、自动增益、语音隔离。WAV，48 kHz，24 bit，单声道，录完不做任何处理。
3. 开头空录 3 秒房间声，然后从头读到尾，停 3 秒再读一遍。读错了不用停，从这句开头重读就行。
4. 语气像给朋友讲东西，口音不用改，要的就是你自己的英文。
5. 可选：几段不同讲法（讲故事、冷静讲解、开场钩子）和随便说 20 秒。这些可以拿来做平均声纹，也可以拿来量像不像。

### 切参考段

```bash
python tools/ref_prep.py 朗读.wav --script tools/ref_read_en.txt --out ref_en
python tools/ref_prep.py 朗读.wav --script tools/ref_read_en.txt --free 随便说.wav --out ref_en
```

它会清理录音（去直流、70 Hz 高通，底噪高才轻度降噪），找出每一句念在哪里，挑出 6.5 到 15 秒、连着念对的几句：
- `ref_en/ref.wav` 和 `ref.txt`：最好的一段，文字和声音一字不差（切下来再识别一遍对得上才算）；`ref_2`、`ref_3` 是备选。
- `ref_en/like/`：参考段以外的每一句，给下面的 `--like` 和 `--voiceprint` 用。
- `ref_en/report.md`：底噪、信噪比、有没有削波、哪句没找到。

### 配音

```bash
python tools/voice.py script_en.txt vo_en --lang en --ref ref_en/ref.wav --like ref_en/like --takes 6 --rate 4.4
```

- `--like`：每一遍都量和你真录音的声纹相似度，挑最像你的；念对字仍然排第一（识别吻合度 0.95 以上的才往下比）。
- `--rate`：目标语速，每秒音节数，不算停顿。你自己念片子里的句子是 4.35 左右。
- `--voiceprint ref_en/like`：用所有对照录音的平均声纹代替参考段自己的声纹，参考段只管念法和节奏。实测相似度只高一点点（0.986 到 0.988），要不要用，盲听决定。
- 换了参考段或声纹，缓存里用旧声音念的句子会自动重配；没换就直接跳过。

### 少一点中文腔：只借音色，整段念

上面的做法给了参考段的逐字稿，模型会连你的念法一起学：节奏、语调、口音都带过来，像你，但中文腔也在。《卡字》英文版最后定的是另一种配方：

```bash
python tools/voice.py script_en.txt vo_en --lang en --voiceprint ref_en/like --voiceprint-only \
  --temperature 0.9 --chunk-words 60 --rate 4.6 --fit-rate --takes 3 --save-voice voice_en
python tools/voice.py script_en.txt vo_en --voice voice_en      # 以后直接用声音包
```

- `--voiceprint-only`：不给逐字稿，模型只用你的平均声纹，节奏和语调用它自己的英文。音色还是你，中文腔少了。
- `--chunk-words 60`：同一段里相邻几句拼成 60 个词以内一口气念，念完按 Whisper 逐词时间切回一句一个文件。一句一句念，句与句之间的语调是断的；整段念是连着的。句间停顿照样由 pace.py / timeline.py 按稿子定。
- `--fit-rate`：一口气念会比一句一句念快一成左右，挑好的那遍整体变速到 `--rate`（最多 ±12%），句内超过 0.45 秒的停顿从中间剪短。整个过程从不往句子里加静音。
- 挑遍：先挑念对的（只在吻合度最高的几遍里挑，整段长，错一个词吻合度也有 0.97），再挑卡顿少、语速接近目标的。卡顿指两个词之间没有标点却断开，或者一个词中间断开。
- 每组念完会对每句再比一次，吻合度低于 0.98 的会提示"听一下"。人名、产品名的念法（`{Chwen=>Qwen}`）多半会被提示，听一下就行。

做这一版时，同一段没念过的新稿子试了十套配比，名字藏起来盲听：参考段换长换短、讲故事和随便说的念法、温度 0.9 和 0.7、只借音色。选中的是只借音色加平均声纹、温度 0.9。千问声纹相似度几套之间只差 0.005，决定还是靠耳朵。

成片混音时，旁白总线上加一道轻处理，选的时候听的就是它（声音包 `voice.json` 的 `bus_filter`）：低频 +1.5 dB、3.5 kHz -1 dB、去齿音、2:1 轻压缩，再 250 Hz -1 dB、6 kHz 以上 +2.5 dB、再去一次齿音。

### 挑参考段的经验

- 平稳讲解的两句话最稳。做《卡字》时试过 8 种参考段，"开场钩子"那种很有劲的读法，只有 60% 的遍数念得一字不差，语速忽快忽慢；随便聊天的录音带着犹豫和拖音，克隆出来也慢，有一段只有 7% 的遍数念对。
- 参考段越长不一定越好：把三种读法拼成 28 秒，相似度反而降到 0.983，语速也偏快。
- 最后要靠耳朵：拿一段**你没念过**的稿子，几种参考各配一遍，名字藏起来盲听，选最像你的。念过的句子不能用来试听，你会下意识拿自己的念法去对。

## 已经有录好的旁白

跳过这一步。录音要和稿子一字不差，然后直接用 `timeline.py --whole`（见第三步）。

## 其他平台

voice.py 依赖 mlx（只在苹果芯片 Mac 上跑）。Windows 和 Linux 上可以：
- 用千问官方的 Python 包在 NVIDIA 显卡上跑同一个模型（未实测）；
- 或者自己录旁白，走 `--whole`。
