# 第六步：检查和发布

AI 说"已完成"，只是它的感觉。要的是测出来的结果。

## 逐帧检查

```bash
python tools/kazi_check.py out/final.mp4 --timeline timeline.json --json out/check.json
```

| 查什么 | 怎么判断 | 不通过怎么办 |
|---|---|---|
| 卡字率 | 每个关键词前 0.35 秒到后 0.15 秒，画面动量至少是前一秒的 1.5 倍，多出画面 0.1% 以上 | 给这个词加一个落点动作，或者把已有动作挪到 `hit()` |
| 随机基线 | 同样的判断放到旁白里每一个时刻上，有多少比例也算卡上 | 基线很高，说明画面一直在乱动，关键词那一下不突出 |
| 黑帧 | 亮度极低的帧（开头结尾 0.5 秒除外） | 查场景切换处有没有空档 |
| 一闪而过 | 某一帧和前后都差很多，但前后两帧几乎一样 | 多半是某个元素少算了一帧，查那一刻的代码 |
| 长时间不动 | 超过 6 秒完全静止 | 加呼吸、轻微的镜头漂移，或者本来就该切了 |
| 响度 | -16.5 到 -12.5 LUFS，真峰值不超过 -1 dBTP | 重跑 mix.py |
| 音轨、片长 | 至少一条音轨；片长和时间表一致 | 封装时漏了音频，或者渲染帧数不对 |

卡字率参考：同一段 19 秒左右的旁白，Opus 和 Sonnet 各做两遍，不装卡字的两遍合计卡上 1/10，装上的两遍 10/10。样本很小，方法、四段原片和局限都在 `bench/README.md`，可以自己复现。

除了量，还要**抽帧看**：每个关键词前后各截一张图，拼成一张对照表，看看落点时画面上到底是什么、有没有两个东西叠在一起、字有没有被遮住。

```bash
# 例：在 3.42 秒截一帧
ffmpeg -ss 3.42 -i out/final.mp4 -frames:v 1 out/frame_3.42.png
```

### 字幕和配音对不对得上

```bash
python tools/caption_check.py timeline.json vo_paced/narration.wav
```

拿真实音频量每条字幕出现、消失的时机，以及逐字变亮的时机：
- 出现：比第一个字开口早 0 到 0.15 秒最好，正好读完淡入。早出现超过 0.25 秒的要查。
- 逐字变亮：每条第一个字的对齐时间和实际开口，相差在 0.08 秒以内。
- 消失：不能在最后一个字收声前就消失；显示不到 0.8 秒的字幕来不及读。
不对的多半是对齐器把句首静音算进了第一个字，先跑第二步的 pace.py。

**全部通过才叫用户**，报告里的数字原样告诉用户。没解决的问题直说，不要藏。

## 发布

片子做完只是一半。观众最先看到的是这些：

- **标题**：说清楚看完能得到什么，别只写主题。
- **封面**：一个主体、一句话、能在手机小图上看清。
- **简介**：一句话说这期讲什么，然后放链接和用到的工具。
- **分段章节**：B 站可以在进度条上分段，每段一个短标签（比如"原理：为什么要卡字"），观众能跳着看。时间点从 timeline.json 的 sections 里取。
- **置顶评论**：链接、勘误、下一期预告。
- **AI 声明**：用了 AI 配音或 AI 生成的画面，在片头和简介里说清楚。
