# 第六步：检查和发布

AI 说"已完成"，只是它的感觉。要的是测出来的结果。

## 逐帧检查

```bash
python tools/kazi_check.py out/final.mp4 --timeline timeline.json --json out/check.json
```

| 查什么 | 怎么判断 | 不通过怎么办 |
|---|---|---|
| 卡字率 | 每个关键词前 0.35 秒到后 0.15 秒，画面动量至少是前一秒的 1.5 倍，多出画面 0.1% 以上 | 给这个词加一个落点动作，或者把已有动作挪到 `hit()` |
| 随机基线 | 同样的判断放到旁白里每一个时刻上，有多少比例也算卡上 | 基线很高，说明画面一直在乱动，关键词那一下不突出 |
| 黑帧 | 亮度极低的帧（开头结尾 0.5 秒除外） | 查场景切换处有没有空档 |
| 一闪而过 | 某一帧和前后都差很多，但前后两帧几乎一样 | 多半是某个元素少算了一帧，查那一刻的代码 |
| 长时间不动 | 超过 6 秒完全静止 | 加呼吸、轻微的镜头漂移，或者本来就该切了 |
| 响度 | -16.5 到 -12.5 LUFS，真峰值不超过 -1 dBTP | 重跑 mix.py |
| 音轨、片长 | 至少一条音轨；片长和时间表一致 | 封装时漏了音频，或者渲染帧数不对 |

卡字率参考：同一段 39 秒的旁白（太阳系八颗行星，九个关键词），Opus 和 Sonnet 各做两遍，不装卡字的两遍合计卡上 1/18，装上的两遍 18/18。样本很小，方法、四段原片和局限都在 `bench/README.md`，可以自己复现。

除了量，还要**抽帧看**：每个关键词前后各截一张图，拼成一张对照表，看看落点时画面上到底是什么、有没有两个东西叠在一起、字有没有被遮住。

```bash
# 例：在 3.42 秒截一帧
ffmpeg -ss 3.42 -i out/final.mp4 -frames:v 1 out/frame_3.42.png
```

### 字幕和配音对不对得上

```bash
python tools/caption_check.py timeline.json vo_paced/narration.wav
```

拿真实音频量每条字幕出现、消失的时机，以及逐字变亮的时机：
- 出现：比第一个字开口早 0 到 0.15 秒最好，正好读完淡入。早出现超过 0.25 秒的要查。
- 逐字变亮：每条第一个字的对齐时间和实际开口，相差在 0.08 秒以内。
- 消失：不能在最后一个字收声前就消失；显示不到 0.8 秒的字幕来不及读。
不对的多半是对齐器把句首静音算进了第一个字，先跑第二步的 pace.py。

**全部通过才叫用户**，报告里的数字原样告诉用户。没解决的问题直说，不要藏。

## 出片：4K 和 HDR

检查都在 1080p 上做，过了再出大的。画面是矢量的，放大两倍渲染不会糊。

### 4K 母版

```bash
cd film && bash ../tools/master.sh Main 8 8      # 合成名、段数、并发
```

分段渲染，中断了重跑同一条命令，已经渲好的段会跳过。出来的是 `out/master/base_4k.mp4`：3840×2160，60 帧，H.264 4:4:4，没有声音。这个文件很大，只当母版用，不直接上传。

### SDR 成片

```bash
ffmpeg -i film/out/master/base_4k.mp4 -i audio/mix.wav -c:v libx264 -preset slow -crf 16 -pix_fmt yuv420p \
  -colorspace bt709 -color_primaries bt709 -color_trc bt709 -c:a aac -b:a 320k -movflags +faststart out/final_4k.mp4
```

### HDR（杜比视界 8.4，基础层是 HLG）

```bash
zsh tools/hdr/hdr_encode.sh film/out/master/base_4k.mp4 audio/mix.wav out/hdr
```

要先装 `dovi_tool` 和 `MP4Box`（GPAC），`python tools/doctor.py` 会查。脚本做四件事：

1. **两张 LUT**（`hdr_lut.py`）：把 sRGB 换成 BT.2020 HLG。纸色定在 150 尼特，看着像纸，不像灯箱；另一张同样的映射，亮度先乘 3.5 倍，给发光的线和字用。
2. **增益遮罩**（`hdr_mask.py`）：从 SDR 成片里逐帧找"暗底上的发光色"，只有这些像素用第二张 LUT，其余保持原样。规则写得很窄，纸面上的红、蓝不会被误伤。
3. **编码**：两张 LUT 各算一遍，按遮罩逐像素混合，转成 10 位 HEVC。码流里的颜色标记直接写死，硬件编码器会忽略命令行里的颜色参数。
4. **杜比视界**：按镜头量出亮度（L1），`dovi_tool` 生成元数据插进码流，`MP4Box` 封成 8.4。另外出一份不带杜比视界的 HLG 文件备用。

换了配色，就告诉它新的颜色，再删掉 `out/hdr/mask.mkv` 重算遮罩：

```bash
HDR_PAPER='#FFFFFF' HDR_MASK_ARGS="--bg '#101418' --glow '#FFD166' --exclude '0,896,1920,1080'" \
  zsh tools/hdr/hdr_encode.sh film/out/master/base_4k.mp4 audio/mix.wav out/hdr
```

- `--exclude` 是不提亮的区域（按 1920×1080 的坐标），默认只排除底部字幕条。角标、标题栏这类固定的东西也写进去。
- 默认用 x265 编码，画质好、文件小，但慢：按试编的速度估算，15 分钟的 4K 片子要四个多小时。`ENC=vt` 换成苹果的硬件编码器，快三四倍，按码率编（`VTRATE`，默认 50M）。
- 编完在 HDR 屏幕上抽几段看：暗场里发光的线应该更亮，纸面的亮度和 SDR 版差不多，字不刺眼。

## 发布

片子做完只是一半。观众最先看到的是这些：

- **标题**：说清楚看完能得到什么，别只写主题。
- **封面**：一个主体、一句话、能在手机小图上看清。B 站要 16:9 和 4:3 两张，字放在正中间，16:9 那张从中间裁成 4:3 也切不到字。用 Remotion 的 `Still` 出图最省事，字体、颜色、角色和片子里一模一样。
- **简介**：一句话说这期讲什么，然后放链接和用到的工具。
- **分段章节**：B 站可以在进度条上分段，每段一个短标签（比如"原理：为什么要卡字"），观众能跳着看。时间点从 timeline.json 的 sections 里取。
- **置顶评论**：链接、勘误、下一期预告。
- **AI 声明**：用了 AI 配音或 AI 生成的画面，在片头和简介里说清楚。
