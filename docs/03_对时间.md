# 第三步：对时间

整套方法里最关键的一步。写动画代码的 AI 听不到声音，这一步把声音变成一张它能查的表。

```bash
# 逐句配音（第二步的产出，规整过停顿）
python tools/timeline.py script.txt vo_paced timeline.json --wav vo_paced/narration.wav --speech-gap
# 一整条现成录音
python tools/timeline.py script.txt - timeline.json --whole 录音.wav
```

- 对齐模型：千问 Qwen3-ForcedAligner-0.6B。把稿子和声音一个字一个字地对上，每个字从第几秒开始、到第几秒结束。
- 逐句模式会按 `| 停顿` 和 `@gap` 把各句拼成一条完整旁白（`--wav`），开头留 `--lead` 秒（默认 1.6）。
- `--speech-gap`：停顿按"收声到开口听到的空白"算，减掉每句自带的首尾静音（pace.py 记下的）。不加的话，停顿是从上一句音频文件结束算起。
- 实测：同一条 19 秒的旁白，整条对齐和逐句对齐，关键词起点相差 7 到 57 毫秒。

## timeline.json 里有什么

```jsonc
{
  "total": 19.34,                       // 全片秒数，画面的总长就用它
  "lines": [{
    "i": 2, "sec": "段落名", "start": 2.71, "end": 7.05,
    "say": "念法", "show": "字幕",
    "words": [{"u": "价", "s": 2.71, "e": 2.86}, ...],   // 念法单位：一个汉字，或一个英文词
    "cap":   [{"c": "价", "s": 2.71, "e": 2.86}, {"c": "涨", "s": 4.15, "e": 4.33, "k": 1}, ...]  // 字幕每个字，k=1 是关键词
  }],
  "sections": {"段落名": {"start": .., "end": .., "first": 1, "last": 6}},
  "gaps": [{"name": "demo", "start": .., "end": ..}],
  "keywords": [{"line": 2, "word": "涨", "t": 4.15, "e": 4.33}]
}
```

## 不对时间会差多少

在一条 11 分钟、78 句的片子上实测：按全片平均语速、用字数去估每句的时间，到第十句，画面就比声音差了 3.7 秒。
同一句话里面按字数均分，中位误差 0.16 秒，最差 1.2 秒。一个落点差 0.2 秒，观众就能感觉到"没卡上"。
所以：**画面里每一个和旁白有关的时刻，都从表里查。**

## 在画面代码里怎么查（starter/src/lib/time.ts）

```ts
import {line, at, atIn, hit, appearBy, keywords} from './lib/time';
const L = line('价格');            // 含"价格"的那一句
at('涨')                           // "涨"开始念的秒数
atIn(L, '一倍', 0, 'e')            // 只在这一句里找，取最后一个字结束
hit('涨')                          // 动作该到位的时刻 = at - 3 帧
appearBy('涨')                     // 新元素最晚出现的时刻 = at - 12 帧
```

找不到词会直接报错，不会悄悄给一个假时间。稿子改了，重跑 timeline.py，画面会跟着动。
